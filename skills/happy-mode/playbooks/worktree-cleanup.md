### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /` and inspect the repository's `git worktree list --porcelain` plus available Happy workspace/task tools. Derive paths from those sources, never a guessed host folder. For each candidate, record size, age, branch, merge state, uncommitted and untracked work, PR state, and known active agents. Use a small rerunnable read-only audit if the inventory is large; its buckets are evidence, not deletion authority.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from available workspace and agent tools, known owners, or the user and cross-check every candidate. The audit has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, ask the known Happy owning agents for state or use permitted history tools and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). An active task can create comparison and reproduction workspaces into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar. Pick model and effort from the current Happy catalog when the tool requires them, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. Untracked files may contain intended work; inspect and name them before classifying any as disposable scratch. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune only the confirmed authorized set. Archive managed Happy workspaces or subtasks through their dedicated tools after confirming ownership and that the user intends archival; archival is final. For unmanaged Git worktrees use ordinary `git worktree remove <verified-path>` and let a dirty-state refusal stop removal. Never force removal or recursively delete an uncertain directory. Verify the final workspace inventory and `df -h /`.
6. Simulators and other reclaimers. Inspect simulator lists and cache inventories with read-only tools first. Remove only the explicitly authorized stale targets, preserving active simulators, runtimes, credentials, and user-kept caches. Use exact IDs from the inventory, not blanket deletion commands or guessed application-state paths.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
