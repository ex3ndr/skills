# Critic assignment

Give a Happy collaborator the grounded explanation, relevant paths, and [the critique rubric](critique-rubric.md), plus one distinct angle to assess.

> Assess [architectural angle] in [bounded subsystem]. Start from this explanation: [explanation]. Verify claims against [paths] and applicable repository instructions. Investigate read-only; do not edit, commit, publish, or run external review services.
>
> Find concrete design problems and describe the trigger, failure or change cost, evidence, and smallest useful improvement. Include counterevidence and existing tradeoffs. Do not turn preferences into defects or repeat claims without checking them.
>
> Return at most five supported findings, ordered by impact. For each, cite files and symbols, describe the scenario and practical consequence, state confidence, and explain how to validate it. If an angle looks sound, say what you checked.

The parent makes the final judgment and resolves disagreement from source evidence. Delegation is optional and must obey current Happy limits and tool schemas.
